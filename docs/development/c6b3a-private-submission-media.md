# C6B-3A Private Story Submission media quarantine

Status: Complete locally on 2026-08-17.

## Delivered boundary

C6B-3A adds the confidential persistence and server-only quarantine foundation
for Story Submission images. `PublicStorySubmissionAttempt` has an opaque
recovery bearer secret stored only as a SHA-256 hash, a 24-hour expiry, an
optimistic version, and `ACTIVE`, `SUBMITTED`, and `EXPIRED` lifecycle states.
`PublicStorySubmissionMedia` belongs to exactly one attempt and carries its
private metadata, ordering, technical lifecycle, checksum, and deletion state.

The allowed technical states are `PENDING_UPLOAD`, `UPLOADED`, `PROCESSING`,
`READY`, `REJECTED`, and `REMOVED`. Only retained `READY` rows can be attached
atomically to an existing submission; attachment closes the attempt. Zero-media
submission remains valid. Rejected or removed rows have no ordinal, and retained
rows are compacted to a stable one-based sequence whose first row is the future
lead image.

The provider-neutral `SubmissionQuarantineStoragePort` exposes only server-side
put, processor read/stat, and cleanup deletion. It has no URL, listing, public
delivery, or browser download API. Server-issued HMAC upload authorizations are
short-lived and bind one attempt, one media row, one nonce, one MIME type, and
the 10 MB ceiling. Their nonce is persisted only as a hash and consumed on
upload. Original filenames never become storage keys.

The foundation accepts declared JPEG, PNG, WebP, HEIC, and HEIF only; it limits
an attempt to ten retained images, 10 MB each, and 60 MB total. It requires five
explicit sensitivity declarations, caps description at 300 characters and
suggested credit at 160 characters, rejects exact SHA-256 duplicates within an
attempt, and deletes rejected/removed binary objects through the server-only
port. Expiry cleanup processes bounded batches of unsubmitted attempts only.

Recovery DTOs and review DTOs are explicit allowlists. Neither can contain an
original/quarantine key, checksum, upload authorization, nonce hash, signed URL,
or provider credential. Review media reads require an active local administrator
with `communications.submissions.review`. Anonymous pre-submission operations
do not invent an administrator audit actor; logs redact submission-media
metadata and quarantine identifiers.

## Deliberately not delivered

This slice does not add a public form, route, action, browser upload, file
signature inspection, image decoding, HEIC conversion, derivative generation,
EXIF handling, malware processing, admin media UI, rights/evidence/clearance,
MediaAsset promotion, Story conversion, public media delivery, or a retention
policy for submitted media. `READY` is a server-side technical state only; it
is not clearance or public eligibility.

## Validation

Focused unit tests cover MIME/size/metadata/sensitivity/order/lifecycle rules,
HMAC scope/tamper/expiry behavior, storage namespace isolation, and logging
redaction. PostgreSQL integration tests cover opaque recovery, upload binding,
limits, duplicate and aggregate rejection, order/remove/delete behavior,
technical transitions, atomic `READY` association, administrative DTO
authorization, expiry cleanup, and stale-version race rejection. The migration
is generated by Prisma and validated through deploy/status/seed/diff alongside
the full unit, integration, lint, type, format, and production build checks.
